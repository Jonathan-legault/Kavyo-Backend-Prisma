# Kavyo Flipp ingestion — operational guide

This clean candidate keeps the **five validated ingestion algorithms unchanged**. The single orchestrator is `scripts/run-flipp-ingestion.mjs`; it runs capture/preview/staging/advertisement promotion/product promotion sequentially, and stops on failure.

## Setup

From the project root: `npm ci`, configure `.env` using `.env.example`, then `npx prisma migrate deploy` and `npx prisma db seed` as appropriate for your environment. **Do not run migrations or seeds against an unverified database.**

## Reproduce an existing capture (read-only by default)

`npm run ingest:flipp -- --capture "data/research/flipp/2026-11-19T19-16-16-948Z"`

## Write to the approved local database

`npm run ingest:flipp -- --capture "data/research/flipp/2026-11-19T19-16-16-948Z" --write --backup-confirmed`

This requires a verified PostgreSQL backup **before running**. All stage safeguards remain in place; only permitted local database targets are supported by the current stage implementations. Source capture must be copied separately: it is deliberately not included in this release ZIP.

## Fresh source capture

`npm run ingest:flipp -- --download` (dry-run database writes)

`npm run ingest:flipp -- --download --write --backup-confirmed` (explicit writes)

The public-source client rate-limits and aborts on denied requests. Confirm permission for production source use and redistribution with the source providers before deployment.

## Stage scripts (internal operational dependencies)

1. `capture-flipp-research.ts` — save complete immutable Flipp raw responses.
2. `preview-b6-flipp-capture.mjs` — source manifest, file integrity and exception analysis.
3. `ingest-flipp-capture.ts` — reconcile `Flyer` and `StagedOffer`.
4. `promote-flipp-advertised-offers.ts` — scope/advertisement eligibility, promotion.
5. `promote-flipp-products.ts` — confident canonical products and links.

**Do not rename/move internal stage scripts** without updating their imports, commands, and rerunning a database replay.

## Acceptance criteria (not yet confirmed for this candidate)

Run `npm test`, `npx tsc --noEmit --project tsconfig.json`, and `npm run build`. Restore the exact pretest DB backup and replay the November 19 capture. Compare the normalized records and hold reasons, not just the row counts. The archived premerge checkpoint reported 47 flyers; 14,699 staged; 13,507 advertised; 558 products; 1,133 links; 0 conflicts. These figures are a target, not a new test result.

## Deployment

The backend is a NestJS app started by `npm run start:prod` after `npm run build`. Configuration requires `DATABASE_URL` and `JWT_SECRET`. Prisma client is generated by `postinstall`. Deployments should use `prisma migrate deploy` after database backup and review. The Flipp capture CLI is **not** an HTTP request handler or a scheduled ingestion job; any deployment automation must separately provision its runtime and permissions.
